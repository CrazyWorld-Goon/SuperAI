# Радар болей — playbook

## Зачем

Собрать formulируемые боли, за которые кто-то уже платит или явно ищет исполнителя.
Радар ≠ продажи в чатах. Радар = вход в backlog для этапов «лиды» и дальше.

## Что считать болью (берём)

- Есть запрос на результат («нужно X к дате», «ищем кто сделает Y»).
- Есть контекст плательщика: бизнес, канал, фриланс-заказ, повторная нужда.
- Можно сформулировать оффер одной строкой и черновую цену.

## Что отбрасываем

- Абстрактные жалобы без исполнителя («всё дорого», «ИИ всех заменит»).
- Просьбы бесплатно / «за опыт» / обмен услугами без денег.
- Серое, обман, накрутки, всё что ломает слово человека за оплату.
- Идеи продуктов «на будущее» без живого спроса в источнике.

## Как прогон (один цикл радара)

1. Пройти источники из `sources.md` (только отмеченные как активные).
2. На каждый кандидат — карточка в `backlog.md` по шаблону.
3. Проставить `signal`: strong / weak.
4. В конце прогона: топ-3 strong → кандидаты на этап «лиды».
5. Не квалифицировать и не писать людям на этом этапе (это этапы 2–3).

## Поля карточки

| Поле | Смысл |
|------|--------|
| id | `pain-YYYYMMDD-N` |
| date | дата находки |
| source | откуда (чат/форум/отзыв/ссылка) |
| who | кто страдает / кто платит (тип, не обязательно имя) |
| pain | боль одной фразой |
| evidence | цитата или пересказ сигнала |
| offer_hint | какой пакет мог бы закрыть |
| price_guess | грубая вилка, если видно |
| signal | strong / weak |
| next | `→ leads` или `park` или `drop` |

## Критерий strong

Хотя бы два из трёх: явный запрос на работу; намёк на бюджет/срок; повторяемость (не разовый каприз).
